### ❌ 没拿，及原因

| 项 | 为什么没拿 |
|---|---|
| `CONFIG_MQ_IOSCHED_ADIOS` | 需要另拉 [firelzrd/adios](https://github.com/firelzrd/adios) 的调度器补丁（就是第 1 份清单说的"移植 ssg io"）。**待做** |
| `CONFIG_CRYPTO_LZ4K` / `LZ4KD` + zram 双重压缩 | 需要 SukiSU 的 lz4kd 补丁。**待做** |
| `CONFIG_ZRAM=y` + `ZRAM_DEF_COMP_LZ4` | 我们是 `ZRAM=m`、`DEF_COMP="lzo-rle"`，但**运行时被模块设成 `[zstd]`** ⇒ 改 config 不会生效 |
| `CONFIG_DAMON_PADDR/RECLAIM/LRU_SORT` | opt14 曾因"DAMON kunit 测试头不进镜像"退过相关改动；启用会加代码，收益未证 |
| `CONFIG_USER_NS/PID_NS/IPC_NS/SYSVIPC/POSIX_MQUEUE/DEVTMPFS` | 是给容器（Droidspaces）用的，**不是性能** |
| `KSU_SUSFS_*` 一整套 | root 隐藏，不是性能；且我们的 KSU 是 `init_boot` 里的 LKM，改内核配置要重刷 `init_boot`（禁区） |
| cmdline 注入（11 项） | 见下 |

### ⚠️ cmdline 注入为什么拿不了

社区往 `init/main.c` 的 `setup_arch()` 之后 `strlcat` 一串：

```
schedstats=disable panic=30 page_alloc.shuffle=1 cryptomgr.notests
rcutree.blimit=1024 workqueue.power_efficient=1 skew_tick=0
random.trust_cpu=on kfence.sample_interval=0 loglevel=3
transparent_hugepage=madvise
```

**其中两项在本机拿不到**：

- `schedstats=disable` —— 本机 `sched_schedstats` **运行时是 1**，是被模块覆盖的，cmdline 默认值会被盖掉
- `transparent_hugepage=madvise` —— 本机 THP 运行时是 `[never]`，同样被模块覆盖

其余几项（`kfence.sample_interval=0`、`page_alloc.shuffle=1`、`cryptomgr.notests`、
`random.trust_cpu=on`、`rcutree.blimit=1024`、`workqueue.power_efficient=1`）**是可以加的**，
但要改 `init/main.c`（代码补丁，CRC 中性）。**待做 P3。**

## 五、⭐ P3b/P3c 实测结论（2026-10-02 03:0x，设备侧取证）

### 5.1 ⛔ P3b（zram lz4kd 双重压缩）—— **划掉，收益 0，而且做不了**

设备侧取证推翻了社区清单的前提：

| 观察 | 事实 |
|---|---|
| `lsmod \| grep zram` | **没有 `zram` 模块**；`/sys/module/zram` **不存在** |
| 设备 zram 从哪来 | `/system_dlkm/lib/modules/**6.1.141-android14-11-o-g6ed3e67335d5**/kernel/drivers/block/zram/zram.ko` —— **官方 GKI 的 zram** |
| `lz4k` / `zstdn` / `zstdn_o` 谁注册的 | **`oplus_bsp_lz4k` / `oplus_bsp_zstdn` / `oplus_bsp_zstdn_o`** —— **OPPO 自己的模块** |
| 我们树里的 zram | `drivers/block/zram/` 只有 `Kconfig Makefile zcomp.c zcomp.h zram_drv.c zram_drv.h`，**Kconfig 里没有 `ZRAM_MULTI_COMP`** ⇒ **无多级压缩**；`crypto/` 下**没有 lz4k/zstdn** |
| 重压缩接口 | `/sys/block/zram0/recomp_algorithm`、`recompress`、`algorithm_params` **全部不存在** |

⇒ **两条独立的死路**：
1. 我们改 `CONFIG_ZRAM_*` **到不了设备** —— 设备用的是 `system_dlkm` 里的官方 zram.ko，
   我们自己编的那个 `zram.ko` 从来没被装上去。
2. 我们树里的 zram **没有多级压缩**，要做得先打补丁；但打了也还是到不了设备。

**⇒ P3b 作废。**

### 5.2 ⚠️ P3c —— 逐项对照本机现值，真正有意义的只有 3 项

| 项 | 社区 | 本机实测 | 真实收益 |
|---|---|---|---|
| `kfence.sample_interval=0` | 0 | **已经是 0**（`CONFIG_KFENCE_SAMPLE_INTERVAL=0`） | **零** —— 我们本来就关着 |
| `schedstats=disable` | disable | **`sched_schedstats = 1`**，来源是 **`CONFIG_SCHEDSTATS=y`** | **真**，而且**纯 config 就能关**（不用改 cmdline！） |
| `rcutree.blimit=1024` | 1024 | **10**（默认） | 真，但很小 |
| `loglevel=3` | 3 | `loglevel=6`（运行时 console=4），dmesg **18444 行** | 小 |
| `workqueue.power_efficient=1` | 1 | `N` | **这是省电设置，不是性能** —— 它让 workqueue 少占核，**增加延迟**。要"快"应保持 `N` |
| `page_alloc.shuffle=1` | 1 | `N` | **这是安全加固，不是性能** —— 打乱 freelist，略增开销 |
| `random.trust_cpu=on` | on | 无 | **只影响开机** |
| `cryptomgr.notests` | — | 无 | **只影响开机** |
| `skew_tick=0` | 0 | 无 | 很小 |
| `transparent_hugepage=madvise` | madvise | `[never]`，被 **`scene_swap_controller/scripts/startup.sh`** 强制 | **要改模块，不是改内核** |

⇒ **P3c 的净收益只有 `CONFIG_SCHEDSTATS=n` 一项值得做**，其余要么已是默认、要么是省电/安全项、
要么只影响开机、要么被模块覆盖。

### 5.3 ⭐⭐ 顺带挖到的真正原因：性能被 OPPO 的 vendor 模块层管着

`lsmod` 里有一整套 **OPPO 私有的调度/内存优化栈**（全是 vendor 模块）：

```
oplus_bsp_sched_assist      1048576   ← 1 MB，挂了 14 个模块，含 sched_walt
oplus_bsp_hybridswap_zram    237568   ← 混合交换 zram
oplus_bsp_schedinfo          229376
oplus_bsp_eas_opt                    ← EAS 优化
oplus_bsp_qos_sched                  ← QoS 调度
oplus_bsp_frame_boost                ← 帧率加速
oplus_bsp_task_overload              ← 负载迁移
oplus_bsp_binder_strategy            ← binder 策略
oplus_bsp_uxmem_opt                  ← 内存优化
oplus_bsp_mm_osvelte                 ← 内存瘦身
oplus_bsp_dynamic_readahead          ← 动态预读
oplus_bsp_file_read_record           ← 文件读记录（学习型预读）
oplus_bsp_zram_opt / zsmalloc / zstdn / zstdn_o / lz4k
oplus_bsp_fg_protect / oplus_exit_mm_optimize
```

**这解释了整件事**：为什么我们内核侧的改动（LTO、HZ、crypto、138 条安全补丁）
机主都"体感用不出来" —— **这台机器的"快不快"实际由 OPPO 这一层 vendor 模块决定，
而它们在只读分区上，我们刷 `boot_a` 碰不到。**

（机主装的 `IMS_VAROS`「官方调度屏蔽」和 SCENE 那套，正是在**试图从用户态盖掉这一层**。）
