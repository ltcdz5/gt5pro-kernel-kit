## 三、⭐ 哪些是**真正有收益**的（分级，不混档）

### ✅ 已实测证实

| 项 | 证据 | 性质 |
|---|---|---|
| **内嵌 `regulatory.db` 消掉固件回退等待** | 那条"固件缺失 → 内核回退等满 60 秒"的开机卡点不再出现 | **开机时长**，正向可复现（当年 opt5 的最大单项收益） |
| **`/proc/config.gz` 不再谎报** | 拆掉 builder 注入的 `config_fix` 后，`IP6_NF_NAT` 现读为 `y` | **可验证性地基** —— 后面所有"改动进没进本机"的判断都靠它 |
| **上游安全/正确性修复真进镜像** | 逐文件用 `ar t out/vmlinux.a` 核对，不是看 `git diff` | **安全/CVE/UAF/泄漏** |
| **网络功能从"不可用"变"可用"** | ipset 15 项、IPv6 NAT/MASQUERADE 可加载可配 | **功能级**（二元判定，不依赖性能测量） |
| **ARM 加密指令激活** | `/proc/crypto` 实测：`sha256-arm64-neon`、`sha3-256-ce`、`aes-ce`、`ccm-aes-ce`、`sm3-ce`、`sm4-ce`、`gcm-aes-ce`、`poly1305-neon`、`essiv-cbc-aes-sha256-ce`… | **密码学路径变快**（TLS / dm-verity / f2fs 加密） |
| **没有丢厂商调度干预** | `oplus_bsp_sched_assist` 加载中、`/proc/oplus_scheduler/sched_assist/sched_assist_enabled=enabled=3`、`lb_stat tick_hit` 有真值 | **"无负向"的证据**（自编内核最常见的坑） |
| **零模块回退** | `lsmod` = **621**，与 opt14 完全一致；`disagrees` 只有原有的 `bluetooth` + `oplus_bsp_game_opt` | **兼容性**（靠两道 CRC 闸门保住） |

### ⚪ 改动确实生效，但**收益未测出**（不许升格成"正向"）

- **ThinLTO**：能建、CRC 安全、`Kernel code` 从 17.5 MB → 17.8 MB，但**镜像反而大 3%**，机主"体感用不出来"
- **HZ 250→300**、**SLAB_MERGE_DEFAULT**、**EROFS LZMA/DEFLATE**、**NET_SCH_ETS/PIE**、**RCU_NOCB**、**LANDLOCK**：已编入，效应在噪声带内
- **BBR + fq**：本机对照时"没进稳态"，量不出差异；校园网/高抖动链路上**理论**更好
- **MGLRU**：Scene 两轮规范化测试（开＝关）都是 39/39 零查杀，且本机杀后台走厂商 `oneclick` 而 `lmkd` 命中 0 ⇒ **这把尺子本来量不到它**
- ~~**减脂三项（opt13）**：生效已证（kfence 节点消失）~~ ⇒ ⚠️ **更正**：只有 KFENCE 节点消失（那项确实生效）；
  UBSAN / INIT_ON_ALLOC 两项**从未关**（当时未进 git）⇒ 理论收益按 1/3 算，**且另两项可补回**

| 项 | 为什么 |
|---|---|
| **ADIOS I/O 调度器** | 上游只有 6.12/6.18/7.3 补丁，**没有 6.1**；移植是大工程 |

## 四、⚠️ 代价与风险（要记着的）

1. ~~**减脂三项 = 主动偏离原厂换性能** —— 关掉的是运行时漏洞缓解网，且本机 `PANIC_ON_OOPS=y`~~
   ⚠️ **更正**：实际只关了 KFENCE 采样；`UBSAN_TRAP=y` 在原厂就是 `y`，所以
   "从记日志变成直接重启"这个对比**不存在**（两边都是 trap）。
   ⇒ **日后出现无来由直接重启，第一个排除项就是它**。
2. **`struct eventpoll` 布局 192→216**（多 `callback_head rcu`）：相对原厂是真实 ABI 变化。
   判低风险的理由是它对外不透明、厂商符号全集 199,295 名里 `eventpoll` 命中 0。
3. **蓝牙族 `.ko` 不载**（`sk_filter_trim_cap` CRC 不符，**基线就对不上**）：但耳机实测能连
   ⇒ 这台机器蓝牙走厂商用户态栈，判**不修**。
4. **`oplus_bsp_game_opt` 不载**（缺 4 个 `android_vh_scx_*` 钩子）：SM8650 侧本来就没有 game_opt 基座。
5. **BBR + fq 劣化概率 15–25%**（有损/共享介质上过度填桶）—— **唯一有已知机制、且真在跑的一条**；
   ~~MGLRU 10–20%（与厂商 per-app memcg 并存是已知嫌疑组合）~~
   ⚠️ **2026-10-03 更正**：MGLRU 那条**不成立** —— 判据来自第三方 Scene 模块的 guard，
   而该 guard 在本机**从未生效**（`startup.sh:613` 写成 `getprop prop`，漏 `$`）；
   且 MGLRU **与原厂 config 逐字相同**（不是我们加的），本机确实在回收活跃区 ⇒ **该开**。
   见 `档案/事故与更正/更正-MGLRU与减脂三项-20261003.md`。
6. **ThinLTO 让镜像大 3%**，icache 局部性可能变差。
7. ⚠️ **更正（2026-10-03）**：本文其它处提到的「减脂三项」**实际只有 KFENCE 采样一项生效** ——
   `CONFIG_UBSAN`（含 `TRAP`/`BOUNDS`/`LOCAL_BOUNDS`）与 `CONFIG_INIT_ON_ALLOC_DEFAULT_ON`
   **仍与原厂相同 = 没关**，因为那三项当时只写在构建产物 `.config`、**未进 git**，
   在后来的 config 归一化中丢失。⇒ **另两项是可补回的纯减法**（写进 `gki_defconfig` 并提交）。

**退路**：`images\` 下 14 件 md5 全部核过，见 `救砖与回退-标准流程-20261001.md` §一。

## 六、⭐ 为什么"性能/续航"到现在一个都没测出

**不是没试，是每条路都撞在同一个硬约束上：效应量 < 本机噪声带。**

- 133 项开销类 config 与原厂**全同**（无白捡）
- 减脂三项理论 `<1%`（合成 7%）vs 功率 **CV 41%**
- I/O 侧噪声带 **20~46%**
- 减脂/BBR/MGLRU 的效应都 ≤2%
- app 冷启动尺子的判据是"三个 app 中位数都要改善 **≥9%**"，而任何内核改动能给的都 ≤2%

### ⭐⭐ 更根本的原因（2026-10-02 新证据）

`lsmod` 里有一整套 **OPPO 私有的调度/内存优化栈**，全是 vendor 模块，在**只读分区**上：

```
oplus_bsp_sched_assist      1048576  ← 1 MB，挂了 14 个模块，含 sched_walt
oplus_bsp_hybridswap_zram    237568
oplus_bsp_schedinfo          229376
oplus_bsp_eas_opt  oplus_bsp_qos_sched  oplus_bsp_frame_boost
oplus_bsp_task_overload  oplus_bsp_binder_strategy
oplus_bsp_uxmem_opt  oplus_bsp_mm_osvelte
oplus_bsp_dynamic_readahead  oplus_bsp_file_read_record
oplus_bsp_zram_opt / zsmalloc / zstdn / zstdn_o / lz4k
oplus_bsp_fg_protect / oplus_exit_mm_optimize
```

**这台机器的"快不快"实际由这一层决定，而刷 `boot_a` 碰不到它们。**
⇒ **在只刷 `boot_a` 的前提下，内核侧没有可证的性能空间。**

## 七、一句话总结

> **相比原厂，我们做了四件有据可查的事**：
> ① 把上游 stable/ACK 里**真能进本机镜像**的安全与正确性修复收进来（约 180 条）；
> ② 把网络能力补齐（ipset 全家 / IPv6 NAT / BBR+fq / 内嵌 regulatory.db 消掉 60 秒开机卡点）；
> ③ 打开 ARM 加密指令、HZ300、ThinLTO 等**已生效但收益测不出**的编译与调度项；
> ④ 建立了**两道 CRC 闸门**，保证零模块回退（`lsmod` 621 与 opt14 一致）。
>
> **性能与续航类到现在一个都没测出收益**，诚实定位是"理论正向、本机未证、每条都留了退路"。
> 而根本原因已经查明：**性能由 OPPO 的 vendor 模块层管着，不在 `boot_a` 里。**
