## 0. 摘要（先看这五条）

1. **P1 · 已确证 · 正在发生：整个蓝牙子系统被拒载。** opt47 上 7 个蓝牙家族模块每次开机都装载失败：net/bluetooth/bluetooth.ko、btsdio/hci_uart/btqca/btbcm.ko、hidp.ko、rfcomm.ko。原因：厂商模块期望的 sk_filter_trim_cap CRC 0xf5845708 ≠ 本内核 0x43b2b8f0（modversions 拒载：disagrees about version of symbol → Unknown symbol (err -22)）。与 opt45/opt47 无关：opt12 的符号表上就已经这样（闸门复跑只报这一个符号）。
2. **P1 证据链（双向闭合）**：① 开机 dmesg 原文（C:\Users\xutengfa\Desktop\gt5pro-kernel\logs\dmesg-opt47-baseline.txt:3504-3532）；② 该次开机的 lsmod 清单里一个蓝牙模块都没有（logs\modules-opt47.txt，620 行）；③ 与 stock 日志做集合差：stock 装得上而 opt47 装不上的，恰好就是这 7 个（反向为空）。
3. **P2 · 第 8 个受害者：oplus_bsp_game_opt.ko 被拒载**（缺 5 个 __tracepoint_android_vh_scx_*，err -2）→ 游戏调优/HYBRID 调度能力缺失。根因不是 opt45：opt45 只改 kernel/sched/ext.c + bpf_struct_ops_types.h 且零导出变化；这些厂商 hook 在本树与全部历史里从未存在（grep + git -S 均为空）⇒ 是厂商源码基线相对出货 GKI 的先天缺口。
4. **本方向没有 P0**：不存在已证的变砖 / 数据永久损坏 / 掉基带 / 频繁重启。BBG(Baseband-guard) 不掉基带（只对 SELinux 域 = su/magisk/ksu 生效，系统与 modem 路径恒 trusted）；CRC 校验未被关闭（version.c 仍 return 0）；config_data 谎报 hack 已被 d56788d59a1f 拆掉；APK 签名绕过与 root 隐藏补丁均未应用。
5. **最值得立刻动手的三件事**：① 修 sk_filter_trim_cap 的 CRC 漂移（或给蓝牙家族补一份自编 .ko 覆盖）——唯一功能已经死了的问题；② 给 fs/f2fs/sysfs.c:783 补上界判断（P32 漏的入口，root 可触发栈越界）；③ 给 i2c opt47 补上游 e984010cda7d 的 device_initialize()（窄窗口 UAF）。
