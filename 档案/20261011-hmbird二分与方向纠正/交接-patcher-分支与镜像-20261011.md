## 3. ★下次接手必看的编译/流程坑★

1. **两份同名 slim.h**：`kernel/sched/slim.h` 与 `kernel/sched/hmbird/slim.h` **互不包含**。
   `core.c:99` 只 include 了 `"hmbird/slim.h"`（后者）。往 `kernel/sched/slim.h` 加 extern 时，
   core.c 看不见，会报 `use of undeclared identifier`（见 `build_stage144.failed1.log:57`）。
   两种可行解：(a) 在 core.c 里补一行 `#include "slim.h"`（opt144 采用）；
   (b) 直接放 `hmbird/slim.h`（但那可能超出任务声明的 in-scope）。
2. **改注释也会改 md5**：删/加空行会让其后所有行号 ±1，凡用 `__LINE__` 的宏都会在二进制里留下不同字符串
   ⇒ 不要假设「只改注释 ⇒ 字节相同」。opt142 rev1(58073e5c) vs rev2(6bd58924) 就是这么来的。
3. **buildX.sh 先 commit 再 make**：编译失败也会留下一个 commit。修好后用
   `git commit --amend -F <msg>` 收敛成一条，避免 optNNN 出现两条提交。
4. **`git checkout -- <file>` 从 index 恢复，不是从 HEAD**：buildX.sh 已经 `git add -A` 过，
   想撤销某个文件要用 `git checkout <commit> -- <file>`。（我在这上面踩过一次。）
5. **AgentTeams 的 changedPaths 必须落在任务声明的 in-scope 列表里**，否则 update_task 直接被拒
   （`... is undeclared`）。改到 in-scope 之外的文件时，要么改回声明内的文件，要么先请 captain 改 in-scope。
6. **reset --hard 会丢分支指针**：切基线前先给当前版本建分支/标签。今晚已建：
   `opt142`=b92e70f14d70、`opt142-rev2`=d0a46fbc52e7、`opt143-doc`=8efba050af86、
   `opt144`=4f46e83f8468、标签 `opt143`=e2ec8157c870。当前 `hmbird-core-stageG`=e50bbdb7a899(opt148)。
