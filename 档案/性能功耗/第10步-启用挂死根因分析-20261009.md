## 0. 一句话结论

**出厂内核里根本不存在 `hmbird_sched_class` 这条启用路径。**

`Image.stock` 的字符串全集中，`hmbird_sched_class` / `bpf_hmbird_reg` / `hmbird_ops_enable` /
`hmbird_ctrl` / `hmbird_module_loaded` / `init_sched_hmbird_class` / `register_hmbird_sched_ops` /
`slim_walt` **命中数全部为 0**（见 §1.2）。出厂用的是 **OPPO 改名的 `ext_sched_class`（`scx_` 符号族）**，
启用位是 `__scx_ops_enabled`；厂商模块通过 `sched_ext_init()` 打开 `ext_module_loaded=1` 来让这条路径生效。

我们的树把 **另一份 SM8750 血统的 `hmbird_sched_class` 家族**（19 文件，Stage A/B/C 引入）**与出厂
`ext_sched_class` 同处一树**，并让它去读写**自己的一套 `__hmbird_ops_enabled` / `hmbird_module_loaded`**。
于是 `scx_enable=1` 触发的不是出厂语义，而是一条**出厂从未被验证过、且与厂内既有状态机完全脱钩**的第三方实现。

> 这不只是「缺个初始化」，而是**语义基准选错了**：候选 1 / 2 / 3 都是这个错位的不同侧面，
> 而 §5 的定位方案正是为了用最小代价把「走到哪一步」与「哪一步与出厂脱钩」同时证死。

## 4. 最小风险定位方案（供 Lead 上机执行；本报告**不执行**）

### 4.0 设计原则

1. **面包屑必须能活过硬挂死**：优先写 **pstore/ramoops**（若 `/sys/fs/pstore` 存在）与 **minidump 区**
   （本树已通过 `scx_get_md_info()` 发布 4 KiB 线性映射缓冲，`hmbird_export.c:118-131`）；
   其次才是 `pr_emerg`（硬挂时 kmsg 可能来不及落盘）。
2. **不新增 /proc 顶层条目**（会破 21 条契约，Stage C §4.1 已证）。复用现有
   `/proc/hmbird_sched/hmbird_debug` 的读侧（`hmbird_debug_show()`，`hmbird.c:3945`），追加一行面包屑即可。
3. **不改导出集**（必须仍 15,489）⇒ 面包屑全局**不加 `EXPORT_SYMBOL`**。
4. 每轮只允许一处增量，**可回退**：`git revert` 单个提交 or 直接刷回 opt60/opt62 备件。

### 4.1 补丁草案 A —— 面包屑（一次成型，后续所有轮都用它）

新增 `kernel/sched/hmbird/hmbird_bc.h`（约 25 行，无导出、无新 proc 条目）：

```c
/* SPDX-License-Identifier: GPL-2.0-only */
/* Stage E：enable 路径可留存面包屑。不加 EXPORT_SYMBOL（导出集必须仍 15,489）。 */
#ifndef __HMBIRD_BC_H
#define __HMBIRD_BC_H

/* 每步一个唯一 id：0 未进入，1..N 递增；-1 表示已走完全程 */
extern atomic_t hmbird_bc_last;      /* 最近一步 */
extern atomic_t hmbird_bc_seq;       /* 步数（用于识别回绕/重复进入） */

static void hmbird_bc(int step, const char *tag)
{
        atomic_set(&hmbird_bc_last, step);
        atomic_inc(&hmbird_bc_seq);
        pr_emerg("HMBIRD_BC step=%d seq=%d %s\n",
                 step, atomic_read(&hmbird_bc_seq), tag);
        /* 双保险：pstore（若已挂载）——硬挂时 kmsg 可能丢 */
        if (hmbird_bc_pstore_ready)
                pstore_console_write("HMBIRD_BC", step);
}
#endif
```

`kernel/sched/hmbird/hmbird.c` 里在 `hmbird_ops_enable()` 的**每个临界边界**插入
`hmbird_bc(N, "…")`，编号固定为：

| step | 插入位置（行号基于 `714fadacba9f`） | 语义 |
|---|---|---|
| 1 | `3767` 函数入口 | 真的进入了 enable |
| 2 | `3775` `check_and_disable_cpuhp()` 之前 | cpuhp 关闭前 |
| 3 | `3780` `check_and_disable_cpuhp()` 之后 | **cpuhp 已关、cpus_read_lock 已拿** |
| 4 | `3782` `mutex_lock(&hmbird_ops_enable_mutex)` 之后 | 互斥已得 |
| 5 | `3807` `cpus_read_lock()` 返回后 | 第二次拿 cpus_read |
| 6 | `3819` `percpu_down_write(&hmbird_fork_rwsem)` 之后 | **fork 已被挡住**（最高危区起点） |
| 7 | `3824` `hmbird_cgroup_init()` 之后 | cgroup 表已建 |
| 8 | `3838` `spin_lock_irq(&hmbird_tasks_lock)` 之后 | 任务表锁已得 |
| 9 | `3846` 第一个迭代循环结束（`hmbird_task_iter_exit` 之后） | **所有任务已 prepare（第一步遍历完成）** |
| 10 | `3855` `preempt_disable()` 之后 | preempt 已关 |
| 11 | `3869` 第二个迭代循环结束（`hmbird_task_iter_exit` 之后） | **所有任务已切到 hmbird 类（第二步遍历完成）** |
| 12 | `3877` `percpu_up_write` 之后 | fork 已放行 |
| 13 | `3883` `cpus_read_unlock` 之后 | `cpus_read` 已放 |
| 14 | `3885` `mutex_unlock` 之后 | 互斥已放 |
| 15 | `3890` `scheduler_switch_done(true)` 之后 | 全程走完 |
| 16.. | `3930 / 3918 / 3925` 三个 err 出口 | 失败路径 |

**预期观测（每轮都一样）**：

1. 写入后立刻 `cat /proc/hmbird_sched/hmbird_debug`：正常返回时能看到最后 step；
2. 若写后挂死：**强制重启**，重启后立刻
   `dmesg | grep HMBIRD_BC`（`pr_emerg` 会进 kmsg）与 `ls /sys/fs/pstore/`；
   能看到的最小缺失 step ⇒ **挂死区间**；
3. 关键分界：
   - 停在 **6** ⇒ 挂在 `slim_walt_enable`/`hmbird_cgroup_init` 或 `percpu_down_write` 本身；
   - 停在 **9** ⇒ 挂在第一步遍历（`hmbird_ops_prepare_task` 的 rq 锁遍历）；
   - 停在 **11** ⇒ 挂在 `SCHED_CHANGE_BLOCK`/`hmbird_check_class_changed` 切类过程（⇒ 直指候选 1/2）；
   - 走到 **15** 然后才挂 ⇒ 挂点在**启用后的运行期**（⇒ 候选 1/3/4 优先）。

**回退动作**：`git revert <BC提交>`；或直接刷回 opt60（`boot md5 5fd7909866e0de04b8e46cd9b388cc2e`）。

### 4.2 补丁草案 B —— 分阶段使能（P0–P4，逐级递增）

> 每一阶段都**只做增量**，前一阶段通过才做下一阶段。全程在 `hmbird_ops_enable()` 内，用
> `#if HMBIRD_ENABLE_PHASE >= N` 包住。默认 `PHASE 0`（不改变出厂/既有行为）。

| 阶段 | 改动 | 意图 | 预期观测 | 若不符的判读 | 回退 |
|---|---|---|---|---|---|
| **P0** | 在 `hmbird_ops_enable()` 第一行 `return -EOPNOTSUPP;`（保留 BC step 1） | 证死「开关本身安全」 | `echo 1` 立即返回、`scx_enable` 读回 1、`dmesg` 仅 BC step=1、无挂死 | 仍挂 ⇒ 问题在 `hmbird_ctrl`/`bpf_hmbird_reg` 之前（proc 写处理），与调度器无关 | revert |
| **P1** | step 1 → 直接 `return -EOPNOTSUPP`（跳过 cpuhp） | 证死 proc→ctrl→enable 的**进入** | BC step=1 出现，返回 -95 | — | revert |
| **P2** | 跑到 step 6 后 `return -EOPNOTSUPP`（`percpu_up_write`+`cpus_read_unlock`+ 解锁后才返回） | 证死「拿 cpus_read + fork 写锁」安全 | BC 到 step=6、无挂死 | 停在 6 之前 ⇒ 死锁在 cpuhp/互斥/cpus_read | revert |
| **P3** | 跑到 step 9 后返回 | 证死「第一步任务遍历（prepare）」安全 | BC 到 step=9 | 停在 7 ⇒ `hmbird_cgroup_init`；停在 8/9 ⇒ 任务遍历 rq 锁 | revert |
| **P4** | 跑到 step 11 但**只切 1 个 CPU 上的 1 个任务**（把第二个循环的 `if` 改成 `if (task_cpu(p) != 0) continue;`） | 把「全量切类」降级为「单任务切类」 | 活着 + BC 到 11 ⇒ 挂因是**规模/并存**；挂死 ⇒ 挂因是**单次切类语义**（直指候选 1/2） | — | revert |
| **P5** | 去掉 P4 的限定，跑满 | 二分定位完成 | 得到确定的挂死 step + 规模条件 | — | 回 opt60 |

**安全边界（硬性）**：
- 每轮上机前确认 **opt60 可回退**（`boot md5 5fd7909866e0de04b8e46cd9b388cc2e`）；
- **每次只刷 `boot_a`**，刷完必须 `fastboot set_active a`；
- 单轮最长观察 90 s（看门狗 ~60-90 s），超时即强制重启，**不要反复写** `scx_enable`；
- **P4 之后若仍挂，禁止再提高规模**，直接转 §5 的修复分支。

## 5. 「若确认是 X，则修法 Y」对照

| 若定位结果 | 判定 | 修法 Y | 代价 / 风险 |
|---|---|---|---|
| **P2 就挂（step ≤ 5）** | cpuhp / 互斥 / `cpus_read_lock` 层死锁 | 把 `check_and_disable_cpuhp()` 的 `cpu_hotplug_disable()` 从 enable 路径移除（改为只在 disable 侧），并复核 `hmbird_ops_enable_mutex` 的持有区间不含 rq 锁 | 小；只动锁序，不动 ABI |
| **P3 挂在 step 7** | `hmbird_cgroup_init()` 的 `kn->id` 索引/遍历出问题 | 把索引从 `cgrp->kn->id` 换成 `cgroup->level` 派生的稳定序号；或先把 `cgroup_ids_table` 全量置 `DEFAULT_CGROUP_DL_IDX` 再做增量；同时修掉 `ids < 0` 的恒假判断（候选 7） | 小；纯内核内部 |

| **P4 挂死 + P4 活着（停在 11）** | **类并存 / 启用位脱钩（候选 1+2）** | **首选：让 hmbird 家族复用出厂 `ext_sched_class` 路径** —— 即把 `hmbird_sched_class` 从 `__sched_class` 段移除、所有 `&hmbird_sched_class` 改为 `&ext_sched_class`，并把 `__hmbird_ops_enabled` 与 `__scx_ops_enabled` 合并为一个启用位；次选：把 `CONFIG_HMBIRD_SCHED_CORE` 的**运行时前提**补齐（在 enable 里同时置 `ext_module_loaded=1` 与 `__scx_ops_enabled`，并让 `task_is_scx()` 同时认两个类） | **大**；触及调度器类拓扑 ⇒ 必须重跑四关（导出集 15,489、493 模块 CRC、闸门1/2） |
| **P4/P5 之下，enable 成功但运行期挂** | 运行期语义（候选 3/4） | ① 把 `slim_walt_ctrl/policy/dump` 统一为**单一所有者**（模块导出 → 内核 extern 引用，或反向），enable 路径补 `slim_walt_enable(true)`；② 在 `hmbird_ops_prepare_task()` 补发 `trace_android_vh_hmbird_init_task(p)`，在 tick/switch 侧补 `trace_android_vh_hmbird_update_load*(…)` | 中；会引入/改变共享符号 ⇒ 必须过**遮蔽判定**（闸门 1 需重新解释） |
| **任何情况下短期内无法修好** | 交付兜底 | 对外发布镜像保持 `CONFIG_HMBIRD_SCHED_CORE=n`（家族不编译），或回退 Stage D（`scx_enable` 恢复「只写值」空壳）；断路器 opt53（`f927d8a259f0fad033e6c9b283066ae7`）保留 | 无风险 |
