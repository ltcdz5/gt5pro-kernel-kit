## 4. 步4：DT `version_type` 兼容层（安全红线）

### 4.1 背景与机制（参考补丁逐字取证）

参考补丁已取回并落盘：`_lab/2026-10-09/scx-step5d/refs/hmbird_fix.patch`（5,843 B，`wanwei1028/oneplus_hmbird_fix@main`）。其 commit message 原文：

> 当使用GKI内核时，由于设备树中定义了oplus,hmbird节点的version_type属性为"HMBIRD_OGKI"，而GKI内核期望的是"HMBIRD_GKI"，导致设备无法启动。

- 节点路径：`of_find_node_by_path("/soc/oplus,hmbird")`
- 子节点：`of_get_child_by_name(node, "version_type")`，属性名 `"type"`，读**字符串**
- 参考实现 `is_hmbird_gki_type()`：`return strcmp(type, "HMBIRD_GKI") == 0;`
- 读失败时参考补丁默认写 `"HMBIRD_OGKI"`
- 我们设备 `/proc/device-tree` 里**没有** `hmbird` 节点 ⇒ 一定走「缺失」分支
- 另证：出厂 `Image.stock` 里**没有** hmbird 的 `version_type` 读取代码（那里的 `version_type` 是 `dwc3`/`devlink` 的），`HMBIRD_GKI`/`HMBIRD_OGKI` 字面量在出厂 `Image` 与厂商 `.ko` 里**都不存在** ⇒ 本兼容层纯属**防御性**，且必须在节点缺失时安全降级

### 4.2 实现要点（`kernel/sched/hmbird_sched_proc_main.c`）

```
hmbird_read_version_type()   static；of_find_node_by_path("/soc/oplus,hmbird")
                             → of_get_child_by_name(node,"version_type")
                             → of_property_read_string(...,"type",...)
                             （子节点缺失时回退读父节点上的 "version_type" 属性）
is_hmbird_gki_type()         仅当 type == "HMBIRD_GKI" 为真（对齐参考补丁写法）
is_hmbird_ogki_type()        仅当 type == "HMBIRD_OGKI" 为真（SM8650 正确类型）
hmbird_dt_type_matches()     安全降级闸门：**只有精确 HMBIRD_OGKI 才为真**
hmbird_dt_version_type_name() 返回当前值（供输出）
```

**安全降级（逐条）**：

- 节点缺失 → `pr_info` 一次，值保持 `"UNKNOWN"`，返回 `-ENOENT`，**继续 init**
- 属性缺失 / 不可读 → 同上，**不返回错误给模块/驱动探测路径**
- 类型不符（含 `HMBIRD_GKI` 以外的任何串）→ 值照存，但 `hmbird_dt_type_matches()` 为 **false**
- 全文件 **无 `panic(` / `BUG(` / `BUG_ON`**（已 grep 断言为 0）
- `hmbird_common_init()` 仍返回 `hmbird_proc_init()` 的结果 ⇒ **init 不会因 DT 而失败**
- 值只**收窄**内建 hmbird 路径的自发行为，**从不主动 enable**；真正 enable 仍只由 userspace 写 `/proc/hmbird_sched/scx_enable` 决定（本树 `scx_enable` 初值 0）

**刻意不做（判据要求）**：

- **不引入 WALT**：参考补丁的 `walt.c/walt.h` 两个 hunk 全部不搬（本树无 WALT）
- **不新增导出**：参考补丁的 `EXPORT_SYMBOL(hmbird_check_version_type)` 不搬。本树 hmbird 是内建的，不需要导出；导出会破坏「15,489 逐名未变」
- 不新增 proc 条目：值通过既有 `hmbird_stats` 条目里**新增一行输出** `DT Version Type: %s (match=%d)` 暴露，便于真机 `cat` 验证，条目集不变

### 4.3 实测证据

- 构建 rc=0，`error:` = 0
- 最终 `Image` 字符串：`/soc/oplus,hmbird` ×2、`version_type` ×8、`HMBIRD_GKI` ×1、`HMBIRD_OGKI` ×1、`DT Version Type` ×1
