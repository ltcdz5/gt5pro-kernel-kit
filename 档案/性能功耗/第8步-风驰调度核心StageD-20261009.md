## 0. 一句话结论

```
写 1 -> hmbird_ctrl(true)  -> bpf_hmbird_reg(NULL)   -> hmbird_ops_enable()  -> atomic_set(&__hmbird_ops_enabled, true)
写 0 -> hmbird_ctrl(false) -> bpf_hmbird_unreg(NULL) -> hmbird_ops_disable()
```

### 2.1 `scx_enable_proc_write()` 的新实现（语义）

```c
int *pval = (int *)pde_data(file_inode(file));
int old = READ_ONCE(*pval);
int val;

if (set_proc_buf_val(file, buf, count, &val))   /* 先解析到局部量 */
        return -EFAULT;

WRITE_ONCE(*pval, val);          /* 先公布"用户意图"，/proc 读回的就是写进去的 */
if (val == old)                  /* 只有真边沿才去拨开关 */
        return count;

#ifdef CONFIG_HMBIRD_SCHED_CORE
        WRITE_ONCE(sw_type, HMBIRD_SWITCH_PROC);
        rc = hmbird_ctrl(!!val);
        pr_info("hmbird_sched: scx_enable=%d -> hmbird_ctrl() rc=%d, enabled=%d\n",
                val, rc, hmbird_enabled());
        if (rc == -EINVAL)
                pr_warn("... hmbird module not marked loaded (hmbird_module_loaded==0); MUST load hmbird module before enable\n", val);
        if (rc)
                return -EFAULT;   /* 出厂语义：激活被拒 -> 写入者看得见 */
#endif
return count;
```

### 2.2 为什么必须 `#ifdef CONFIG_HMBIRD_SCHED_CORE`

`hmbird_ctrl`、`sw_type`、`__hmbird_ops_enabled` **只在 `kernel/sched/hmbird/` 参与编译时存在**（`obj-$(CONFIG_HMBIRD_SCHED_CORE)`）；而 `hmbird_sched_proc_main.c` 是 **`CONFIG_HMBIRD_SCHED` 就编**的（`build_policy.c` 里 `#ifdef CONFIG_HMBIRD_SCHED`）。
出厂 `arch/arm64/configs/gki_defconfig` 第 12 行就是 `CONFIG_HMBIRD_SCHED=y`、**没有** CORE —— 不加这道门控会直接 `undefined reference`。门控外保留"只存值"的老行为，**出厂配置逐字不变**。

### 2.3 与出厂 `hmbird_sched_proc.c` 的逐条对齐 / 有意偏离

| 点 | 出厂 `hmbird/hmbird_sched_proc.c` | 本轮 | 判定 |
|---|---|---|---|
| 写进 int | `set_proc_buf_val(..., pval)` 直写 | 解析到局部量再 `WRITE_ONCE(*pval, val)` | 等价，且这样才能可靠判"值变了没有" |
| 打标 | `WRITE_ONCE(sw_type, HMBIRD_SWITCH_PROC)` | ✅ 同 | **对齐** |
| 拨开关 | `hmbird_ctrl(*pval)` | ✅ `hmbird_ctrl(!!val)` | **对齐** |
| 失败返回 | `return -EFAULT` | ✅ `return -EFAULT` | **对齐** |
| 每次写都拨 | 每次都调 `hmbird_ctrl()` | **仅边沿**调用 | **有意偏离**：任务要求"当值发生变化时"；副作用是重复 `echo 1` 不再回 `-EBUSY` |
| 日志 | 无 | `pr_info` 必打 + `-EINVAL` 额外 `pr_warn` | **有意新增**（本轮的可观测性要求） |

## 3. `hmbird_ctrl()` 的返回路径（`kernel/sched/hmbird/hmbird.c:3992`）

```c
int hmbird_ctrl(bool enable)      /* 非 static；未 EXPORT_SYMBOL（vmlinux.symvers 中 grep 命中 = 0） */
{
    if (!atomic_read(&hmbird_module_loaded)) {                 /* ← 唯一的"厂商模块"前置检查 */
        hmbird_switch_log(...);  return -EINVAL;               /*    本轮日志会点名这一条 */
    }
    if (enable && state ∈ {ENABLED, ENABLING, PREPPING}) {
        hmbird_switch_log(...); hmbird_err(ALREADY_ENABLED, ...);  return -EBUSY; }
    if (!enable && state ∈ {DISABLING, DISABLED}) {
        hmbird_switch_log(...); hmbird_err(ALREADY_DISABLED, ...); return -EBUSY; }

    if (enable) return bpf_hmbird_reg(NULL);    /* -> hmbird_ops_enable(NULL)  -> atomic_set(&__hmbird_ops_enabled, true)  @3841 */
    else        return bpf_hmbird_unreg(NULL);  /* -> hmbird_ops_disable()     -> atomic_set(&__hmbird_ops_enabled, false) @3644 */
}
```

- `hmbird_ops_enable()` 还会失败并返回 `-EBUSY`（`check_and_disable_cpuhp()` 失败、或 `hmbird_ops_helper` 建不出来时返回 `-ENOMEM`），失败路径在 `3841` 之后另有把 `__hmbird_ops_enabled` 置回 `false` 的 `3863`。
- `hmbird_enabled()` = `atomic_read(&__hmbird_ops_enabled)`（`include/linux/sched/hmbird.h:56`），全树 ~20 处门控都看它 —— 所以 `enabled=%d` 这一栏就是**真正的生效位**，/`scx_enable` 那个 int 是**用户意图**，两者从此不再混为一谈。

## 4. `hmbird_module_loaded` 谁来置位（本轮最重要的发现）

```
start_kernel()
  └─ sched_init()                                       kernel/sched/core.c:10253
       └─ #ifdef CONFIG_HMBIRD_SCHED_CORE
            init_sched_hmbird_class()                   kernel/sched/core.c:10254  (__init)
              └─ hmbird_misc_init()                     kernel/sched/hmbird/hmbird.c:4315
                   └─ set_hmbird_module_loaded(1)       kernel/sched/hmbird/hmbird_misc.c:145
                        └─ atomic_set(&hmbird_module_loaded, 1)   hmbird.c:3985
```

- 变量本体：`atomic_t hmbird_module_loaded = ATOMIC_INIT(0)`（`hmbird.c:24`）；setter `set_hmbird_module_loaded()`（`hmbird.c:3983`）**全树只有 `hmbird_misc.c:145` 一个调用者**。
- **出厂布局里 `hmbird_misc.c` 属于厂商模块 `oplus_bsp_sched_ext.ko`**，所以出厂的注释写"**MUST load hmbird module before enable hmbird scheduler**"，这个标志要等 `insmod` 才立起来。
- **本树布局不同**：Stage A/B 就把 `hmbird_misc.c` 编进了内核（`hmbird_all.c` → `CONFIG_HMBIRD_SCHED_CORE=y`），于是这个标志**在开机时就已经是 1**。
- ⇒ **行为推论（对上机很关键）**：CORE=y 的本内核里，`echo 1 > scx_enable` **不会**撞上 `-EINVAL`；它会一路走到 `bpf_hmbird_reg(NULL) → hmbird_ops_enable(NULL)`。若真机上仍打出 `rc=-22 (EINVAL)`，说明 `init_sched_hmbird_class()` 没跑到（而不是"厂商模块没加载"）——日志已经把两种情形分开写了。
- 本轮**没有绕过**这道检查（任务红线）：代码里原样保留，注释写明 `MUST load hmbird module before enable`。
