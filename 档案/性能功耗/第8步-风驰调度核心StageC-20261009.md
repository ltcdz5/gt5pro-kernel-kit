## 2. core.c 接线清单（本轮全部改动集中在这一个文件）

全部包在 `#ifdef CONFIG_HMBIRD_SCHED_CORE` 内 ⇒ **出厂配置（CORE=n）行为一字不变**。

| 位置 | 改动 | 语义 |
|---|---|---|
| 文件头 include | `hmbird/slim.h`、`hmbird/hmbird_shadow_tick.h`、`hmbird.h` | 让 core.c 看见家族符号 |
| `__task_prio()` | `hmbird_sched_class` → `MAX_RT_PRIO + MAX_NICE + 1`（120） | core-sched 排序把 hmbird 压到 fair 之后 |
| `sched_can_stop_tick()` | `!hmbird_enabled() && rq->nr_running > 1` ⇒ false；`hmbird_enabled() && !hmbird_can_stop_tick(rq)` ⇒ false | 与既有 scx 分支同构，由类自己回答"能否停 tick" |
| `select_task_rq()` | `!is_cpu_allowed() && sched_class != &hmbird_sched_class` 才回退 | hmbird 任务不回退到 `select_fallback_rq` |
| `sched_fork()` | `hmbird_pre_fork()`；`task_on_hmbird(p)` ⇒ `p->sched_class = &hmbird_sched_class`；`out_cancel` 加 `hmbird_cancel_fork()` | fork 时把 hmbird 任务交给 hmbird 类 |
| `sched_cgroup_fork()` | `hmbird_fork(p)` | 与 `scx_fork()` 并列 |
| `sched_post_fork()` | `hmbird_post_fork(p)` | 与 `scx_post_fork()` 并列 |
| `scheduler_tick()` | `hmbird_notify_sched_tick()`；hmbird 启用时跳过 `trigger_load_balance()`；`scheduler_tick_handler(NULL, NULL)` | 1ms shadow tick 的 tick 侧入口 |
| `__pick_next_task()` | `hmbird_notify_pick_next_task(rq, p, class)` | 与 `scx_notify_pick_next_task()` 并列 |
| `__schedule()` | `sched_switch_handler(NULL, preempt, prev, next, prev_state)` | 上下文切换钩子 |
| `__setscheduler_prio()` | `task_on_hmbird(p)` ⇒ `&hmbird_sched_class` | setscheduler 时切类 |
| `__sched_setscheduler()` | `hmbird_check_setscheduler(p, policy)`（不通过则 `goto unlock`） | 拒绝切进被禁的 HMBIRD |
| `sched_init()` | `WARN_ON_ONCE(sched_class_above(fair, hmbird))`、`(hmbird, idle)`；`init_sched_hmbird_class()` | 类顺序自检 + 初始化 |
| `cpu_cgroup_css_online()` | `hmbird_tg_online(tg)` | cgroup 上线时初始化 hmbird task group |
| `cpu_cgroup_attach()` | `hmbird_change_rt_sched_prop(css, task, task->prio)` | display/touch/multimedia cgroup 的 RT 任务打 `sched_prop` |
| `cpu_legacy_files[]` | `hmbird.deadline` cftype（read/write `cgroup_*_hmbird_deadline`） | cgroup → hmbird 全局 DSQ deadline 索引 |

## 3. 与 OPPO/fengchi 补丁的**有意偏离**（逐条给理由）

| # | 补丁做法 | 本轮做法 | 理由 |
|---|---|---|---|
| 1 | 在 core.c 新增 `hmbird_sched_change_guard_init/fini` | **不加** | 本树 core.c **已经有** `sched_change_guard_init/fini`（**函数体逐字节相同**）与 `SCHED_CHANGE_BLOCK`，且 hmbird.c 已经用它 ⇒ 再加一份是死代码 |
| 2 | `prio_less()` 加 `hmbird_prio_less()` 分支 | **不加** | 家族里**没有** `hmbird_prio_less` 符号（会链接失败）；且 `pa == MAX_RT_PRIO+MAX_NICE+1` 已被既有 `CONFIG_SCHED_CLASS_EXT` 分支覆盖 |
| 3 | `__sched_setscheduler()` 全程持 `hmbird_tasks_lock` | **不加锁** | 该处唯一的 hmbird 调用 `hmbird_check_setscheduler()` 只 `lockdep_assert_rq_held()`，**不要求** `hmbird_tasks_lock`；而补丁的锁要跨 `recheck:` 与多个 `goto` 路径成对释放 ⇒ 锁失衡风险大、收益为零 |
| 4 | `case SCHED_HMBIRD:` 加进两个 switch | **不加** | 本树 `SCHED_HMBIRD == SCHED_EXT == 7` ⇒ 重复 case 编译错误；`SCHED_EXT` 标签已覆盖 |
| 5 | `cgroup_read_hmbird_deadline()` 里的 `if (i < 0)`（i 是 u8） | **删掉** | 恒假条件，只会产生告警 |

## 4. 任务第 2、3 项：**有意不做**，附证据

### 4.1 第 2 项「注册 hmbird_sched_proc.c 的 13 条非重叠条目」——**做了会破厂商模块**

`hmbird_sched_proc.c` 建 **34** 条，`hmbird_sched_proc_main.c` 建 **21** 条，差集 **13** 条：

```
cluster_separate  cpu7_tl  cpu_cluster_masks  frame_per_sec
highres_tick_ctrl_dbg  hmbird_preempt_policy  scx_gov_ctrl
scx_shadow_tick_enable  slim_gov_debug  slim_walt_ctrl
slim_walt_dump  slim_walt_policy  yield_opt
```

拿厂商模块 `oplus_bsp_sched_ext.ko`（`vendor-ko/vendor_dlkm/`）的字符串表逐名核对：

| 条目 | 模块自己也建？ |
|---|---|
| `cpu7_tl` / `frame_per_sec` / `highres_tick_ctrl_dbg` / `scx_gov_ctrl` / `scx_shadow_tick_enable` / `slim_gov_debug` / `slim_walt_ctrl` / `slim_walt_dump` / `slim_walt_policy` | ✅ **是（9/13）** |
| `cluster_separate` / `cpu_cluster_masks` / `hmbird_preempt_policy` / `yield_opt` | ❌ 否（4/13） |

⇒ **内核侧若注册这 9 条，模块的 `proc_create()` 会返回 NULL ⇒ 模块 init 失败**——正是 Stage B 排除该文件的同一机制。
剩下 4 条**不在出厂内核的 `/proc/hmbird_sched` 契约内**（契约 = 已入树的 21 条，Stage A/B 已与 `Image.stock` 对账 21/21），加进去等于偏离出厂语义。
**结论：13 条一条都不注册**；"按需"的答案就是"不需要"。（`hmbird_preempt_policy` / `cluster_separate` 作为内核全局已存在，家族可读，只是不暴露成 proc 条目。）

### 4.2 第 3 项「`slim_walt_*` 语义统一」——**只登记，不改**

- 模块 `oplus_bsp_sched_ext.ko` **自己创建** `slim_walt_ctrl` / `slim_walt_dump` / `slim_walt_policy` 条目并持有**自己的那份变量**（4.1 已证）。
- 内核侧的那三个全局是 Stage B 为让 `hmbird.c` 链接而定义的**独立副本**（`hmbird_misc.c`）。
- ⇒ `hmbird.c` 里 9 处 `if (slim_walt_ctrl)` **恒读到 0**（模块写的是另一份），即 slim_walt 相关分支实际不生效。
- **本轮不改**：统一需要一个跨模块共享机制（要么内核导出、要么模块导出后内核引用），会牵涉**遮蔽判定**，属于 Stage D 决策项。**已登记**。
