# 第 5 步 e · DT \`hmbird/version_type\` 兼容层（独立补丁）

> 日期：2026-10-09 ｜ 基线：\`bb7d854291b7\`（opt59）｜ 产物：\`_lab/2026-10-09/dt-compat/dt-version-compat.patch\`
> 性质：**防御性 / 可选**。见 §5「当前是否必需」。

## 1. 背景与机制

- 厂商补丁 \`wanwei1028/oneplus_hmbird_fix/hmbird_fix.patch\` 记载：**内核期望的 hmbird 类型与设备树不符 ⇒ 设备无法启动**。
  这与 opt43 的**整机硬挂死 + PMIC 复位**是同一类机制：类型不一致发生在极早的调度器初始化路径上，没有安全降级。
- SM8650 的正确类型是 **\`HMBIRD_OGKI\`**（依据 \`murongruyan/cezai-hmbird-ko\` SoC 表：SM8850→EXT、SM8750→OGKI、**SM8650→OGKI**、MT6991/6993→OGKI、MT6995→EXT）。
- 本机实测 \`/proc/device-tree\` **没有 hmbird 节点**。
- 本树**没有 WALT** ⇒ 参考补丁里动 \`kernel/sched/walt/*\` 的部分**不适用**，本补丁**不引入 WALT**。

## 2. 实现要点（2 个新文件 + 1 行 Makefile）

| 文件 | 变更 |
| --- | --- |
| \`kernel/sched/hmbird_version.c\` | 新增（183 行）：DT 读取 + 安全降级 + 唯一导出 |
| \`kernel/sched/hmbird_version.h\` | 新增（31 行）：\`enum hmbird_dt_version\` + 3 个原型 |
| \`kernel/sched/Makefile\` | +1 行 \`obj-y += hmbird_version.o\` |

- 读取路径：\`/soc/oplus,hmbird/version_type\` 的 \`type\` 属性（即 \`/proc/device-tree/soc/oplus,hmbird/version_type/type\`），
  用 \`of_find_node_by_path()\` + \`of_get_child_by_name()\` + \`of_property_read_string()\`。
- **懒探测 + 幂等缓存**：首次调用时探测，\`smp_store_release\` 发布结果、\`smp_load_acquire\` 读取。
  不用 initcall 是**刻意**的——\`sched_ext\` 的集成点在 \`sched_init()\`（早于所有 initcall），arch_initcall 会太晚。
- 属性值先 **strscpy 到本地缓冲再 \`of_node_put()\`**：\`of_property_read_string()\` 返回的是 DT blob 内的指针，不依赖 \`of_node_put\` 保活。
- 兼容扁平写法 \`/soc/oplus,hmbird { type = "..."; }\`（子节点缺失时回退读父节点同名属性）。
- 对外：\`bool hmbird_is_ogki(void)\`（唯一导出）、\`enum hmbird_dt_version hmbird_version_type(void)\`、\`const char *hmbird_version_name(void)\`。
- \`CONFIG_OF=n\` 时整段走 \`#else\` 分支，**无条件编译通过**（不依赖新增 Kconfig）。

## 3. 降级路径（安全方向：**绝不 panic / BUG**）

| 情况 | 结果 | \`hmbird_is_ogki()\` |
| --- | --- | --- |
| \`CONFIG_OF=n\` | UNKNOWN | false |
| \`/soc/oplus,hmbird\` 节点缺失（**本机实测**） | UNKNOWN | **false** |
| \`version_type\` 子节点缺失 | UNKNOWN | false |
| \`type\` 属性缺失 / 空串 | UNKNOWN | false |
| \`type\` 存在但不在表内 | UNKNOWN（\`pr_warn\` 一次） | false |
| \`type = "HMBIRD_OGKI"\` | OGKI | **true** |

**UNKNOWN 一律映射到 false**：false 的语义是"与未打补丁的 GKI 内核完全一致"，
即本层**只会在正面命中时开启 OGKI 行为**，永远不会因为解析失败而猜一个类型。
判据 4 的两条（节点缺失 ⇒ 降级；有节点且 \`type="HMBIRD_OGKI"\` ⇒ OGKI）由此同时满足。
表内另外两型 \`HMBIRD_GKI\` / \`HMBIRD_EXT\` 只记录不改行为。

## 5. 当前是否必需（重要）

「风驰实机可用-最小修复清单-20261009」§6 已记录：**实机 \`oplus_bsp_sched_ext.ko\` 里已无该闸门**
（\`strings\` 无 \`of_find_node_by_path\` / \`version_type\`）⇒ 那套是**上一代**机制。
所以本补丁**不阻塞主线**，价值在于：
1. 换用**带 DT 闸门**的旧版 \`.ko\`（或未来版本）时，内核侧有安全降级，不会重现 opt43 的硬挂死；
2. 给 sched_ext 集成路径一个**可查询的、不会崩的**类型判据（后续要按类型分流时直接用）。

## 7. 如何应用到主线

\`\`\`bash
cd ~/kwork/cctv18/repo/local/kernel_workspace/common      # HEAD = bb7d854291b7 或其后代
git apply --check /path/to/dt-version-compat.patch && git apply /path/to/dt-version-compat.patch
\`\`\`
- 补丁**只新增 2 个文件 + 改 Makefile 1 行**，不碰任何既有 C 文件 ⇒ 与主线其他改动**不会冲突**（除非有人也动 \`kernel/sched/Makefile\` 的同一位置）。
- 应用后如需在 sched_ext 路径使用：
  \`\`\`c
  #include "hmbird_version.h"      /* kernel/sched/ext.c 等 */

  \`\`\`
  厂商模块侧可直接 \`extern bool hmbird_is_ogki(void);\` 并按 \`MODULE_LICENSE("GPL")\` 链接（\`EXPORT_SYMBOL_GPL\`）。
- 回退：\`git checkout -- kernel/sched/Makefile && rm kernel/sched/hmbird_version.[ch]\`。
