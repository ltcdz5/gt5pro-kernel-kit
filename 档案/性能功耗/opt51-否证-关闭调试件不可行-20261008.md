# opt51 否证记录（2026-10-08）

**假设**：关闭 KASAN / KASAN_HW_TAGS / KFENCE / DEBUG_LIST / SCHED_DEBUG / SCHEDSTATS / BUG_ON_DATA_CORRUPTION
可以换来性能/内存收益（机主已批准“安全换性能”）。

**实测结论：不可行（硬拦）**。构建 opt51 后用全量模块审计（493 个厂商 .ko）核对：

- **493/493 个模块全部出问题**；
- `__list_add_valid` / `__list_del_entry_valid` 两个导出**直接消失**（分别有 132 / 103 个模块导入它们）—— 由 `CONFIG_DEBUG_LIST` 提供；
- 所有模块出现大量 CRC 不符（例如 `adsp_sleepmon.ko` 36 条、`atmel_mxt_ts.ko` 52 条）；
- 连 `sk_filter_trim_cap` 的 CRC 都从 0x43b2b8f0 变成 0xe4b963e8 ⇒ 说明 `struct task_struct` 等核心类型布局被改动。

**定案**：这 6 项被厂商模块**锁死在 ABI 上**，与出厂 config 一致不是“保守选择”，而是**必需**。opt51 已回滚，现役保持 opt50。

**副产品**：本轮审计脚本升级为 `tools/gate_all_modules.py`（扫描全部厂商 .ko，同时检查
“符号缺失”与“CRC 不符”——补齐了 gate2 只查已存在符号 CRC 的盲区）。
