# 风驰实机可用 · 最小修复清单（依据实机 .ko 契约）

> 日期：2026-10-09 ｜ 依据：`档案/性能功耗/参考-官方vendor-sched_ext接口契约-20261009.md`（126 符号 / 31 节点 / 9 钩子）
> 用途：让 `oplus_bsp_sched_ext.ko` 在自编内核上**真正生效**（不只是"能装载"）

## 0. 现象与根因（已锁定）
设备实测：按依赖序 `insmod` 成功（`game_opt` → `sched_assist`(已在载) → `sched_ext`，rc=0）✓，但
**`/proc/hmbird_sched` 不存在** ✗、**`scx_enable` 不存在** ✗、`dmesg` 无新增 ✓。
⇒ 根因：**`hmbird_dir` 全局指针恒为 NULL**（见 §1）✓

## 1. 必修：`hmbird_dir` 赋值（一行）
- 现状：`kernel/sched/hmbird_export.c` 只有 `EXPORT_SYMBOL_GPL(hmbird_dir);` ✓
  而 `kernel/sched/hmbird_sched_proc_main.c` 里 `hmbird_dir` 是 `hmbird_proc_init()` 的**局部变量** ✗
- 后果：模块 `proc_create` 落到 **`/proc` 根**（同名不同父），`/proc/hmbird_sched` 永不出现 ✗
- 修法：把 `proc_mkdir("hmbird_sched", NULL)` 的返回值**赋给全局 `hmbird_dir`** ✓（删掉同名局部 ✓）
- 验收：`ls /proc/hmbird_sched` 出现且**条目数与实机契约一致**（内核侧 3 目录 31 条，全部 `0666` ✓）

## 2. 必查：`register_hmbird_sched_ops`（实机模块唯一注册入口）
- 实机模块缺它会**直接 `Unknown symbol`** ✓（比"无节点"更早失败 ✓）
- 我们树实现在 `kernel/oplus_cpu/sched/sched_assist/sa_hmbird.c` ✓，被**两道 config 闸门**挡住：
  `CONFIG_OPLUS_FEATURE_SCHED_ASSIST`（整个目录不编译 ✗）+ `CONFIG_HMBIRD_SCHED`（`#ifdef` 包住 ✗）
- **注意**：设备实测 `insmod` 成功 ⇒ 该符号当前由**已在载的 `oplus_bsp_sched_assist`** 提供 ✓ ⇒ 内核侧**不要重复导出**（遮蔽风险 ✗）
- 行动：确认开关打开后**不产生同名导出** ✓；若产生 ⇒ 立刻回退该导出 ✓

## 3. 必做：`CONFIG_HMBIRD_SCHED=y` 后的条目集对齐
- 内核侧"前半套"= `hmbird_sched_proc_main.c`：`/proc/hmbird_sched` **+25 条**、`/proc/hmbird_sched/slim_walt` +4、`slim_freq_gov` +2，全部 `0666` ✓
- 模块侧"后半套"由实机 `.ko` 建 ✓（含 `hmbird_common_open/show/write` ✓）
- **不得重叠** ✗：两套都建同名条目 ⇒ 模块 `proc_create` 返 NULL ⇒ init 失败 ✓

## 4. 必核：127 条 CRC 全对齐
- `CONFIG_MODVERSIONS=y` 下**名字对、CRC 错同样装载失败** ✗
- 复核对象（实机模块期望值，已知的几条）：`task_is_scx 0xb3071c68`、`hmbird_dir 0x947ca90f`、`non_ext_task 0xfd0701e9`、`iso_masks 0xcb6a4c44`、`scx_get_md_info 0x35454d24`、`ext_module_loaded 0x2d91f265`、`__scx_ops_enabled 0x85f027ab` ✓
- 工具：`gate_vko_crc.py`（会拒绝装载的模块 = 0 ✓）

## 5. 已满足（别动 ✗）
- `scx_get_md_info()` **必须返回非 NULL**（否则 `hmbird_misc_init` **BUG()** ✗）—— opt55 已发 `kmalloc(0x1000)` ✓
- `iso_masks` **成员顺序不可改** ✓（模块按裸偏移 0x00/0x08/0x10 取 ✓）
- **禁止**用 scx 分支版覆盖 `hmbird_export.c` ✓（那版少 `iso_masks`/`scx_get_md_info` ✗）
- 9 条钩子 opt55 全部已导出 ✓（7 条 `__tracepoint_android_*` + 2 条 `DECLARE_HOOK` ✓）

## 6. 已降级（不是必需 ✓）
- **DT `version_type` 兼容层**：实机 `.ko` 里**已无**该闸门 ✓（无 `of_find_node_by_path`/`version_type` 字符串 ✓）⇒ 那套是**上一代**机制 ✓；保留补丁但不阻塞主线 ✓
- `/sys/kernel/sched_ext/enabled` **恒为 0 是正常的** ✓（上游 BPF struct_ops 状态；我们从不注册 BPF 调度器 ✓）；`scx_enable` 走 **`/proc/hmbird_sched/scx_enable`**（0666 ✓）与它**无绑定** ✓

## 7. 验收（实机八条 + 一条硬信号）
1. **能正常启动** ✓（第一优先）
2. `/proc/hmbird_sched` 存在且条目数/权限符合契约 ✓（**31 条 / 0666**）
3. `/proc/hmbird_sched/scx_enable` 存在、可读写 ✓
4. 按依赖序 `insmod` 三模块 `rc=0` ✓、`lsmod` 三个都在 ✓
5. `dmesg` **出现 `<hmbird_sched>` 标签** ✓ ← **fork 真在跑的硬信号** ✓
6. `Unknown symbol`/`disagrees about version`/`Oops`/`BUG:`/`panic` **全 0** ✓
7. 493 模块审计 missing=0/crc=0；闸门2 拒载=0；闸门1 遮蔽=0 ✓
8. 回退件在手：opt55 `aca40a5cc4c81f7516bf734bc1bdacaf` ✓、断路器 opt53 `f927d8a259f0fad033e6c9b283066ae7` ✓
- ⛔ **不主动 register 调度器** ✓（opt43 整机硬挂死 + PMIC 复位 ✓）
