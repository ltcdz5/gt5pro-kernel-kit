# 风驰（hmbird/sched_ext）完整配方与五层状态

> 日期：2026-10-09 ｜ 设备：真我 GT5 Pro（RMX3888 / **SM8650** / ColorOS 16）｜ 内核：6.1.141 自编（现役 opt55，opt56/opt57 已构建未刷）
> 本文把"全套可用风驰"拆成 **5 层**，逐层给出：现状 / 依据（来源与证据）/ 验收判据 / 风险。

---

## 0. 一句话结论

**"全套可用风驰" = ①DTBO 节点（SM8650 用 `HMBIRD_OGKI`）＋ ②内核侧 OGKI 形态的 hmbird/sched_ext（ferstar `scx` 分支 = OPPO 私有命名）＋ ③厂商模块 `oplus_bsp_sched_ext.ko` ＋ ④控制器写 `scx_enable=1` ＋ ⑤云控（prjname/COSA/gameswitch）**

其中 **③⑤ 已具备**（模块可装载、云控有现成模块），**①缺**（我们设备 DT 里根本没有该节点），**②进行中**（块1+块2），**④现成**。

## 2. SoC → HMBIRD 类型表（**关键，直接决定 ① 的写法**）

| SoC | 云控 ID（prjname）| HMBIRD 类型 |
|---|---|---|
| SM8850 / SM8850P / SM8845 | 24831 | `HMBIRD_EXT` |
| SM8750 / SM8750P | 24851 | `HMBIRD_OGKI` |
| **SM8650 / SM8650P** | **23851** | **`HMBIRD_OGKI`** ← 我们的 SoC |
| MT6991 / MT6993 | 24813 | `HMBIRD_OGKI` |
| MT6995 | 25815 | `HMBIRD_EXT` |

> ⚠️ **更正记录**：曾据 `wanwei1028/oneplus_hmbird_fix` 推测 SM8650 需 `HMBIRD_GKI` —— **错**。SM8650 是 **`HMBIRD_OGKI`**。因此内核侧目标变体 = **OGKI**（与 ferstar `scx` 分支的 OPPO 私有命名一致），方向未跑偏。

### DTS 结构（两种，别混）
**OGKI**（SM8650 ✓）—— 子节点名是 `version_type`：
```dts
fragment@15 {
    target = <0xffffffff>;
    __overlay__ {
        oplus,hmbird { version_type { type = "HMBIRD_OGKI"; }; };
        reboot_reason { /* 保留原有内容 */ };
    };
};
```
**EXT** —— 用 `config_type` 结构，锚点优先唯一直接子节点 `oplus-gpio`，无则用含 `oplus_sim_detect` 的唯一 overlay。

安装器要求**唯一**的 `fragment@15`/`__overlay__`/`reboot_reason`/`oplus,hmbird`；缺失/重复/类型冲突 ⇒ **中止不写**（严谨）。

## 3. 两条 DT 路线（二选一）

| 路线 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **A. 写 DTBO 分区**（cezai 模块）| 读当前 slot 原厂 DTBO → 校验 → 只加节点 → **复用原厂 AVB 信息写回**；重启后内核直接读持久节点 | 一次到位、与社区一致、模块自带云控流程 | **写分区** ✗（AVB 处理不当会起不来）；需要 `fastboot` 与镜像备份 |
| **B. 内核侧兼容层**（`hmbird_fix.patch` 思路）| 内核读 DT `version_type`，**不匹配/缺失时自适应** | 不动分区 ✓、可随内核回退 ✓ | 要在内核里加兼容逻辑（块1 顺带做 ✓）；行为需与出厂对账 ✓ |

**建议**：优先 **B（内核侧兼容层）** —— 与块1 同批落地、可回退、零分区风险 ✓；若 B 无法覆盖厂商模块的全部期望，再考虑 A（并在电脑旁、备好 DTBO 备份与 fastboot ✓）。

## 4. 关键接口与硬约束清单（块1/块13 的验收依据）

1. **开关名**：`scx_enable`（控制器写它；我们树现在只有 `/sys/kernel/sched_ext/{enabled,switched_all}` ✗ ⇒ 块1 必须带进 `scx_enable`）
2. **还缺的 2 个符号**：`register_hmbird_sched_ops`、`test_task_is_hmbird` —— 在**我们树** `kernel/oplus_cpu/sched/sched_assist/sa_hmbird.c`，被两道闸门挡：`CONFIG_OPLUS_FEATURE_SCHED_ASSIST`（目录不编译）+ `CONFIG_HMBIRD_SCHED`（`#ifdef`）⇒ 块13 处理
3. **`hmbird_export.c` 的 10 个导出绝不能丢**（`iso_masks`/`scx_get_md_info`/`task_is_scx`/`ext_module_loaded`/`non_ext_task`/`hmbird_dir`/`__scx_ops_enabled`/`slim_for_app`/`scx_sched_rq_stats`/`scx_irq_work_lastq_ws`）；ferstar 版只有 8 个 ⇒ **是子集，不许覆盖** ✗
4. **`ext.h` 缺 include guard** ⇒ 块1 必须补（否则二次包含炸 `redefinition of scx_wake_flags`）
5. **`CONFIG_HMBIRD_SCHED` 保持 `default n`**：出厂内核建 `/proc/hmbird_sched` + **前半套** proc 条目，厂商 `.ko` 建**后半套**（字符串一一互补）；同时存在会让模块 `proc_create()` 返 NULL ⇒ init 失败
6. **`non_ext_task` 保持 `atomic_t`**（补丁里的 `u64` 是 `struct snap_misc_t` 的**字段**，不是全局）；厂商 .ko 期望 `non_ext_task` crc=`0xfd0701e9`、`hmbird_dir` crc=`0x947ca90f`，本树**逐位相同** ✓
7. **`get_hmbird_cpu_exclusive` 由 `oplus_bsp_game_opt.ko` 导出** ⇒ 内核**不得**再导出（遮蔽 = opt6 致砖机制）
8. **DT 类型不匹配 ⇒ 设备无法启动**（`hmbird_fix.patch` 的明确记载）⇒ 这是 **opt43 整机硬挂死 + PMIC 复位的机制性解释**，块1 必须配兼容层

## 6. 实机验收清单（顺序不可颠倒）

3. `ls /proc/hmbird_sched` 出现（出厂内核有）

5. `insmod oplus_bsp_sched_ext.ko` rc=0，`lsmod` 有它；`Unknown symbol`/`disagrees` = 0
6. 全量 493 模块审计 missing=0 / crc=0；闸门2 拒载=0；闸门1 遮蔽=0
7. **⛔ 不主动 register 任何 scx 调度器**（Scene 的 `game_scheduler` 何时启用由机主决定；opt43 曾整机硬挂死 + PMIC 复位）
8. 回退件常备：`boot-v1.1-opt55-repacked.img`（`aca40a5cc4c81f7516bf734bc1bdacaf`）；断路器 = **opt53**（无 `/sys/kernel/sched_ext`，任何 scx 都无法注册）

## 7. 风险与红线

- **红线**：任何让内核"期望某变体"的改动，**必须同时具备 DT `version_type` 兼容层**（缺失/不匹配 ⇒ 起不来）
- **红线**：新增导出不得遮蔽厂商模块已导出名（`register_hmbird_sched_ops`/`test_task_is_hmbird` 归 `oplus_bsp_sched_assist.ko`；`get_hmbird_cpu_exclusive` 归 `oplus_bsp_game_opt.ko`）
- **红线**：不改核心结构布局（会破 493 模块 CRC）；不 `make olddefconfig`；只刷 `boot_a` 且刷后 `fastboot set_active a`
- **流程**：刷机前必须三关全绿并留证据；树必须始终可编；推送一律用 **Windows 侧 git**（WSL 侧 remote 指 gh-proxy 会永久挂死）
