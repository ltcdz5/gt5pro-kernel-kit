# ⛔ 结构体改动的 CRC 影响面**不能靠穷举** —— opt39 事故与第 6 次闸门救场（2026-10-03）

> **本文记录一次"差一步刷砖"的事故，以及它推翻的一条方法论。**
> 结论：**改结构体成员 ⇒ 影响面必须实测（闸门2），任何"穷举证明"都不可信。**

---

## 一、想做什么（opt39 = B）

`struct nf_conntrack_expect` 加一个 `possible_net_t net`，让 `nf_ct_exp_net()` 不再读 `exp->master`：

```c
/* 改前 */
static inline struct net *nf_ct_exp_net(struct nf_conntrack_expect *exp)
{
	return nf_ct_net(exp->master);      /* master 是 SLAB_TYPESAFE_BY_RCU，
	                                       可能已 kmem_cache_free ⇒ 读已释放对象 */
}
/* 改后 */
	return read_pnet(&exp->net);
```

**理由充分**：`nf_ct_exp_net()` 有 **7 个调用点**（`expect.c:51/390/440/550/636`、`ecache.c:236`、
`netlink.c:3100`），opt38 只堵了 `exp_seq_show` 那一条；而且这是 **CVE-2026-31414** 的真修法。

**改动只有 3 处**（2 文件 +16/−1），而且找到一个天然咽喉：
**全部 26 处 expectation 分配都走 `nf_ct_expect_alloc(struct nf_conn *me)`**
（sip/ftp/amanda/irc/nft_ct/tftp/broadcast/sane/pptp/netlink/ipvs/h323_main…）
⇒ `me` 那时必然活着 ⇒ 在那一处 `write_pnet(&new->net, nf_ct_net(me))` 就够。
`nf_ct_expect_cachep` 用 `sizeof()` 建，自动适配。唯一的另一处 `exp->master = ct`（netlink:3565）
上面已经调过 alloc ⇒ 冗余。

## 三、★ 被推翻的方法论（本文最重要的产出）

做这个改动的子代理给了"**穷举证明**"：
> 会漂 CRC 的导出符号 = 原型里出现 `struct nf_conntrack_expect *` 的 **25 个**（含名字里没有 expect 的
> `nf_nat_follow_master`、`nf_nat_exp_find_port`）；这 25 个 ∩ 4754 条厂商真引用名 = **空集**
> ⇒ **闸门2 必然仍 = 1**，风险 = 0。

**实测（两版 `vmlinux.symvers` 逐符号比）：**
```
CRC 变化总数 = 109        （不是 25！）
  其中 expect/conntrack 直接相关 = 70
  ★ 间接牵连（名字里完全看不出来）= 39
     例：__skb_get_hash / __skb_flow_dissect / __skb_get_hash_symmetric …
```

**为什么 25 → 109**：`__skb_get_hash(struct sk_buff *)` 的 CRC 取决于 **`struct sk_buff` 的成员列表**，
而 `struct nf_conntrack_expect` 通过某种类型链被牵连进去（`struct sk_buff` 里确有
`unsigned long _nfct` 这类 conntrack 相关字段）。

### ⇒ 结论（写进纪律）
1. **改结构体成员 ⇒ 该结构体出现的所有导出符号的 CRC 都变**，而且会**沿类型链传播**到
   **名字里完全看不出来**的符号（`__skb_get_hash` 就是活例）。
2. **影响面不能靠"名字里含 X"穷举** —— 任何这类"证明"都要当成**假设**，必须实测。
3. **唯一可信的判据 = 跑闸门2**。这次它一次就报出 7 个模块、3 个符号、精确到厂商期望值与本内核值。
4. 连带推论：**"改结构体但 CRC 不变"这条路基本不存在** —— genksyms 按**成员列表**算，
   哪怕只加一个成员、哪怕复用现有 padding 不改字节布局，CRC 也会变。
   ⇒ **凡是"必须改结构体"的修法，在本项目（只刷 boot_a、厂商 .ko 不可动）里基本都是死路。**

## 四、这条教训对"opt39 该做什么"的影响

opt39 原计划 = B（结构体化），**已证不可行**。
⇒ 靶子必须换成**纯 `.c`**（或子系统私有头里**不动结构体**的改动）。
