# 账本法（用 builder 自己的账本判"某个修复进没进树"）—— 2026-10-03

> 方法由 `net/netfilter` 那一轮的子代理发现，**本文记录用法与首次应用的结论**。

---

## 一、账本在哪（都是 builder 自己攒的）

| 路径 | 内容 | 规模 |
|---|---|---|
| `~/his/*.json` | 各轮收割的 triage / apply / keep / plan 结果 | 17 个 json |
| `~/stable_gap/` | **stable 6.1 里"抓到但没落地"的补丁**（**只有 `.h` 改动**） | **1250 个** |
| `~/stable_gap_h/` | 同上（`.h` 分类） | 462 个 |
| `~/stable_gap_c/` | 同上（`.c` 分类） | 9 个 |
| `~/ack3_gap/` | ACK 第三轮没落地的 | 104 个 |
| `~/ack4_gap/` | ACK 第四轮没落地的 | 340 个 |

**命名规律**：`<批次号>__<路径下划线化>.patch`，例：
`0141__fs__ext4__ext4.h.patch` = 批次 0141 里 `fs/ext4/ext4.h` 的那块改动。
⚠️ **批次号不是 commit id**，是 builder 自己的编号。

## 二、怎么用

```sh
# 1) 搜某子系统有没有"没落地"的补丁
grep -rliE '<子系统关键词>' ~/stable_gap ~/stable_gap_h ~/stable_gap_c ~/ack3_gap ~/ack4_gap

# 2) 看它能不能打上
git apply --check ~/stable_gap/<文件名>.patch

# 3) ★ 关键：看它加的符号在树里【有没有人用】
grep -rn '<新增的符号名>' fs/<子系统>/ | grep -v '\.h:'
#    —— 0 次 ⇒ 是死代码（配套的 .c 半边不在），加了没有功能收益

# 4) 看它改的 .h 会不会动【已导出符号的 CRC】
grep -E '^0x[0-9a-f]+\s+<子系统前缀>_' out/vmlinux.symvers    # 该子系统导出了什么
grep -xF -f <该子系统导出列表> /home/builder/abi/vko_syms_real.txt   # 厂商有没有引用
```

## 三、首次应用：ext4 / jbd2（结论：**没货**）

### 查到的
`~/stable_gap/` 里有 **7 个 ext4 补丁**：
```
0141__fs__ext4__ext4.h.patch            +7
0154__fs__ext4__ext4.h.patch            -2
0155__fs__ext4__ext4.h.patch            +10
0159__fs__ext4__ext4.h.patch            +1
0160__fs__ext4__xattr.h.patch           +10
0166__fs__ext4__ext4.h.patch            +5/-4
0166__fs__ext4__extents_status.h.patch  +2/-2
```
**7 个全部 `git apply --check` 通过（rc=0）**，但：

### ⛔ 为什么不能用
1. **全是"头文件半边"**：它们加的是给配套 `.c` 用的 inline 辅助函数
   （`ext4_get_maxbytes` / `ext4_inode_orphan_tracked` / `DX_HASH_LAST` / `ITAIL`）。
   **实测这些符号在树里的 `.c` 中使用次数 = 0** ⇒ 加进去只是**未使用的 inline 函数 = 死代码**，
   **零功能收益**（配套 `.c` 半边不在 `stable_gap/` 里，也没被应用）。
2. **其中一个会直接编译失败**：`0160__fs__ext4__xattr.h.patch` 想在 `xattr.h` 里加
   `#define xattr_check_inode(...)`，而 **`fs/ext4/xattr.c:283` 已经自己定义了一个同名宏**
   ⇒ **宏重定义冲突**。

### ✅ 但顺带确认了一件有用的事
```
ext4 导出符号（ext4_ 开头）= 0 个
jbd2 导出符号（jbd2_ 开头）= 60 个，其中被【厂商真引用名】引用的 = 0 个
```
⇒ **改 `fs/ext4/*.h`、`fs/jbd2/*.h` 的 CRC 风险 = 0**
（没有任何厂商模块依赖 ext4/jbd2 的任何导出）
⇒ 这条对**将来**做 ext4/jbd2 的修复很有价值（可以放心改它们的私有头）。

## 四、方法论价值

**账本法一次就排除了 ext4 这条线**（否则要花一整轮读代码才发现那 7 个补丁是碎片）。
⇒ 以后**挑靶子时先跑一遍账本法**：
```sh
grep -rliE '<子系统>' ~/stable_gap ~/stable_gap_h ~/stable_gap_c ~/ack3_gap ~/ack4_gap
```
- **有 `.c` 改动且能打上、且加的符号有人用** ⇒ 真货
- **只有 `.h` 改动** ⇒ 大概率是碎片（配套 `.c` 不在），要按第 3 步验"有没有人用"
