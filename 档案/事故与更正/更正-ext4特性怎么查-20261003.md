# 更正 + 两条新判定：ext4 特性怎么查（inline_data / fast_commit）—— 2026-10-03

> 本文更正我自己的一个**方法错误**，并给出两条**已确证的"走不到"判定**。

---

## 一、我错在哪

我先前查"本机 ext4 有没有 `inline_data`"时用了：
```sh
grep -o 'inline_data' /sys/fs/ext4/sda2/features      # ← 这个文件【不存在】
```
`cat` 返回空，我把它当成了"特性为 no"。**错。**

**真相**：ext4 的**每设备目录**里**没有 `features`**。实测 `ls /sys/fs/ext4/sda2/` 得到的是：
```
delayed_allocation_blocks err_ratelimit_burst errors_count extent_max_zeroout_kb
first_error_block first_error_errtype ... inode_goal inode_readahead_blks journal_task
lifetime_write_kbytes mb_group_prealloc ... msg_count reserved_clusters
session_write_kbytes sra_exceeded_retry_limit trigger_fs_error warning_count ...
```
⇒ **没有 `features`**。而顶层的 `/sys/fs/ext4/features` 是**另一个东西**（内核**支持**哪些特性，不是设备**启用**了哪些），
且它在本机 `cat` 出来是**空**。

⇒ **教训（第 7 次踩同类坑）**：
**`cat <不存在的路径>` 返回空 ⇒ 必须区分"文件不存在"和"内容为空"。**
判据：先 `ls` 确认文件存在，或用 `[ -e path ]` 断言。
（本项目的"子串当命中"累计 6 次，这次是"空输出当否定"。）

## 二、正确查法（两种，互相印证）

### 方法 1：`tune2fs`（本机有 `/system/bin/tune2fs`）
```sh
tune2fs -l /dev/block/sda2 | grep -i 'Filesystem features'
```
实测输出：
```
Filesystem features: has_journal ext_attr dir_index filetype needs_recovery
                     extent sparse_super large_file huge_file uninit_bg dir_nlink extra_isize
```

### 方法 2：直接读磁盘超级块特性标志（不依赖任何工具）
```sh
# 超级块在分区偏移 1024
# s_feature_compat    @ sb+0x5C  ⇒ 分区偏移 1116
# s_feature_incompat  @ sb+0x60  ⇒ 分区偏移 1120
# s_feature_ro_compat @ sb+0x64  ⇒ 分区偏移 1124
dd if=/dev/block/sda2 bs=1 skip=1116 count=12 | od -An -tx1
```
实测：
```
sda2   compat=0x0000002c  incompat=0x00000046  ro_compat=0x0000007b
sdf3   compat=0x0000002c  incompat=0x00000046  ro_compat=0x0000007b
sde11  compat=0x0000002c  incompat=0x00000042  ro_compat=0x0000007b
loop5  compat=0x00000038  incompat=0x00000242
loop11 compat=0x00000028  incompat=0x00000042
```

**关心的位**（ext4 定义）：
| 位 | 值 | 含义 | 实测 |
|---|---|---|---|
| `s_feature_incompat` bit 6 | `0x40` | `EXTENTS` | **有** |
| `s_feature_incompat` bit 15 | `0x8000` | **`INLINE_DATA`** | **无** |
| `s_feature_incompat` bit 7 | `0x80` | `64BIT` | 无 |
| `s_feature_compat` bit 10 | `0x400` | **`FAST_COMMIT`** | **无** |

## 三、两条已确证的判定

| 缺陷 | 依赖的特性 | 实测 | 判定 |
|---|---|---|---|
| **CVE-2025-38222**（`fs/ext4/inline.c:396`，形参 `unsigned int` 截断 ⇒ `BUG_ON` panic） | `inline_data` | **全部 ext4 均为无**（两种方法一致） | ⛔ **走不到**（`ext4_has_inline_data()` 恒 false） |
| **jbd2 #6 线索**（`fs/jbd2/journal.c:881-884`，`j_fc_get_buf` 先推进 `j_fc_off` 后 bmap） | `fast_commit` | **全部 ext4 均为无** | ⛔ **走不到** |

⇒ 这两条**都不做**。ext4/jbd2 这条线到此为止：opt39 落了 3 项（jbd2 NULL 解引用、信用额低估、i_size 上界），
opt40 落了 1 项（sysfs UAF），**剩余候选全部因特性未启用而不可达**。
