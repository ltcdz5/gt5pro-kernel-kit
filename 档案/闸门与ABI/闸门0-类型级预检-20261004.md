# 闸门0：类型级 ABI 预检（2026-10-04 落地）

> 起因：机主指出「闸门2 应该从**经验**变成**结构**」——ACK 自带 ABI monitoring（build_abi.sh + ABI_DEFINITION + STG/abidiff），
> 改动前先做类型级 diff，比「编出来再试载 493 个模块」便宜一个数量级，而且直接给出**传染半径**。

## 一、我们拿什么实现

本机已具备 **libabigail**（abidw/abidiff 2.4.0）与 pahole 1.25；我们的 `out/vmlinux` 同时带 **BTF 与完整 DWARF**（.debug_info 在）⇒ 可直接提取 ABI 语料。

| 工具 | 作用 |
|---|---|
| tools/gate0_abi_snapshot.sh | 用 abidw 从 vmlinux 提取 ABI 语料（实测 530 MB vmlinux → **1 分 40 秒 / 18.5 MB XML**） |
| tools/gate0_type_diff.py | 比较两份语料：符号 CRC 漂移、类型定义变化、**导出符号可达半径**，并给 PASS/FAIL |

**语料自带 modversions CRC**（libabigail 读的是内核 `__crc_*`）⇒ 符号级判定**不需要厂商 .ko**，
这正好补上闸门2 的盲区：闸门2 只能发现「**有模块引用**的符号」漂移。

## 二、双对照实验（2026-10-04 实测，两个方向都成立）

| 对照 | 内容 | 结果 |
|---|---|---|
| **负对照** | opt45 → opt47（只改 i2c 函数体，正是当前现役版） | **PASS**：CRC 漂移 0 ｜ 类型变化 0 ｜ 新增/消失 0 ⇒ 证明不会对「纯函数体改动」误报 |
| **正对照** | opt45 → opt46（BBRv3，闸门2 曾报 367/493 模块拒载） | **FAIL**：CRC 漂移 **2546** ｜ 类型变化 **6** ｜ 新增符号 3（`tcp_plb_*`） |

正对照点名的 6 个类型：`netns_ipv4`、`rate_sample`、`tcp_bbr_info`、`tcp_congestion_ops`、`tcp_sock`、`tcp_ca_event`（enum 新增 `CA_EVENT_TLP_RECOVERY`）
—— 与人工逐行定位的结论完全一致。

**耗时 1.0~21.8 秒**（取决于是否算可达半径），且**不碰厂商模块、不刷机**。

## 三、三级级联（这次把「为什么改 6 个类型能炸掉 367 个模块」量化了）

    改 6 个类型
      ⇒ 10,406 / 15,437 个导出符号「结构上可达」（理论半径，gate0 算出）
      ⇒  2,546 个导出符号「CRC 实际漂移」（gate0 算出）
      ⇒    473 个符号被厂商模块引用 ⇒ **367 / 493 个模块拒载**（闸门2，会砖）

`473 ⊆ 2546 ⊆ 10406` —— 每一层的口径不同，这条链把它们对齐了：
**理论可达 ≠ 实际漂移 ≠ 有模块引用 ⇒ 只有最后一层才决定砖不砖**，但前两层能**提前**告诉我们「这个补丁会不会碰到 ABI」。

## 四、用法（每次做候选版本时）

    # 0) 一次性：为「参考版本」留一份语料（例如每次发布后）
    tools/gate0_abi_snapshot.sh <参考版本的 out/vmlinux> refs/abi/v1.1-opt47.xml

    # 1) 候选版本构建完（有 out/vmlinux）后
    tools/gate0_abi_snapshot.sh out/vmlinux /tmp/cand.xml

    # 2) 结构级预检
    tools/gate0_type_diff.py refs/abi/v1.1-opt47.xml /tmp/cand.xml out/vmlinux.symvers
    # PASS ⇒ 结构零变化（可放心走闸门1/2 + 刷机）
    # FAIL ⇒ 看它点名的类型：触及 hub 类型（sock/tcp_sock/task_struct/net/...）基本等于判砖，先别构建厂商侧验证

## 五、局限（诚实列出）

1. **仍需要一次构建**才能拿到 vmlinux（abidw 读的是产物）；它省掉的是「厂商模块试载/上机」这一层，不是编译本身。
2. **语料要按版本留存**：比较是相对「参考版本」的，参考语料必须与现役交付版一致（建议每次发布后立刻存一份）。
3. **18.5 MB/份** 体积不小 ⇒ 放仓库外本地 refs；公开仓库只放工具与方法。
4. 可达半径是**上界**（BTF/DWARF 视角），实际漂移以 CRC 那一层为准；两者一起看才有意义。
