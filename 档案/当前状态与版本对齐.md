### ★架构事实（2026-10-13 确认，必须知道）★
`scx` 调速器**不是内核自带的**，它由厂商模块 `oplus_bsp_sched_ext.ko` 提供；
设备上**唯一** insmod 它的是风驰守护模块 `service.sh` 里的厂商模块栈循环
（`oplus_bsp_game_opt` → `oplus_bsp_sched_assist` → `oplus_bsp_sched_ext`）。
⇒ **停用守护模块 = 同时移除 scx 调速器**。做 A/B 时必须把这一条算进去，
否则「关掉守护后 scx 不见了」会被误读成内核缺陷。

## 同步清单（每次出片）
1. 本文件"当前"表更新（版本串 / 镜像 md5 / 开关状态）
2. CHANGELOG.md 追加一条（日期 + 变更 + 三关数字）

4. 任何新增导出必须复核遮蔽（对照 refs 里的厂商导出表）
5. ★★出片前必跑 CRC 定点覆写门禁（2026-10-12 新增，血的教训）★★
   - **构建成功 ≠ 可以出片**。`genksyms` 对具名结构体变量只哈希类型名，`iso_masks` / `task_is_scx` /
     `sk_filter_trim_cap` 三个符号的 CRC 必须用 `tools/patch_crc_targeted_v2.py` **定点覆写**成厂商 .ko 的
     `__versions` 期望值；漏跑时**构建 rc=0、无任何报错**，只有设备侧 `oplus_bsp_sched_ext.ko` 静默拒绝加载
     （`scx` 调速器消失）。**opt151 就是这么漏的**（早前把 opt150 也算作漏跑版本，已更正：
     见 `F:\工作区\_audit\更正-漏跑CRC只发生在opt151.md`）。
   - 顺序：构建 → **跑 `patch_crc_targeted_v2.py`** → 门禁断言 → 打包 → 刷机。第 2 步不可省略。
   - ⚠ 覆写工具**即使全部 SKIP 也返回 rc=0** ⇒ 必须用独立门禁检查**产物字节**：
     `bash gate_crc_v2.sh <Image> [<vmlinux>]`（3 个真实槽位 + new==1 + old==0 + `_text` 取自符号表）、
     `bash gate_crc_diff5.sh <前> <后>`（等长 + 恰好 12 字节不同 + 连续 3 个 4 字节槽）、
     `python3 gate_crc_pre.py <Image> [<vmlinux>]`（★必须用 `python3` 调用★）。**全部 exit=0 才算过。**
   - 打包后必须回读断言：`kernel_size` 正确、版本串正确、且 `new iso x1 / old iso x0 / new tscx x1 / old tscx x0`。
   - 完整流程（命令 + 预期输出 + 失败判据）：`F:\工作区\_audit\出片流程-四步门禁.md`
