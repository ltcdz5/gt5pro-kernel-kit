## 一、★ 新增第三条可达性判据（本版最重要）

**此前判"本机走不走得到"用两条**：
1. `out/.config` 里的开关
2. `out/<目录>/` 下有没有对应 `.o`（+ 调用点没被 `#ifdef` 排除）

**本版发现这两条不够** —— 必须加第三条：

> **3. 用户态真的有那个工具、并且真的在用它。**

### 铁证（opt38 的 #1/#5）
```
内核侧：CONFIG_IP_SET=y，net/netfilter 编入 117 个 .o（含全部 ip_set_*）
用户态：/system/bin/ipset、/vendor/bin/ipset、/system_ext/bin/ipset —— 【都不存在】
        /proc/net/ip_set —— 不存在
        /proc/slabinfo 里【没有 ip_set 对象】 ⇒ 从未创建过任何 set
```
⇒ **ipset 的 dump UAF（#1）与空桶不释放（#5）在本机走不到**：
代码是真的、修复是对的，但**用户态没有 ipset 工具，这条路径永远不被触发**。

**先例对照**：`mm/cont_pte_hugepage.c`（94 KB，被 `vmscan.c` 引用）因 `CONFIG_CONT_PTE_HUGEPAGE=n` 而没编。
⇒ 两个先例合起来说明：**"编了"和"有人用"是两件独立的事**。

### 实操：怎么查第三条
```sh
# 1) 用户态二进制在不在
ls /system/bin/<tool> /vendor/bin/<tool> /system_ext/bin/<tool> /odm/bin/<tool>
# 2) 内核侧有没有"被用过"的痕迹
ls /proc/<对应节点>                 # 如 /proc/net/ip_set
grep -i '<对象名>' /proc/slabinfo    # 对象从未分配 ⇒ 从未用过
# 3) 有没有活跃的进程/条目
ps -A | grep <相关进程>
cat /proc/sys/net/netfilter/nf_conntrack_count   # 例：conntrack 535 条 ⇒ 在用
```

### 本版四项修复的**真实可达性**（据第三条重判）
| # | 修复 | 可达？ | 依据 |
|---|---|---|---|
| #4 | tcp_sack 非对齐读 | ✅ **可达** | 28 条 TCP 连接；SACK 是 TCP 默认协商 |
| #3a | exp_seq_show 判空 | ✅ **可达** | `/proc/net/nf_conntrack_expect` 可读；conntrack 535 条活跃 |
| #1 | ipset dump UAF | ❌ **不可达** | 无 ipset 用户态、无 set、slab 无对象 |
| #5 | ipset 空桶不释放 | ❌ **不可达** | 同上 |

**结论**：opt38 的四项里，**两项真可达、两项"正确但走不到"**。
（修复本身无害且正确 —— 若将来用户态引入 ipset，它们就是对的。）

## 二、那 10 条 `WARNING` 的解释（**不是我们的回归**）

```
7× fs/proc/generic.c:377   proc_register+0x124        ← /proc 重名注册
1× fs/sysfs/group.c:61     internal_create_group      ← sysfs 重名注册
1× "Unprivileged eBPF is enabled, data leaks possible via Spectre v2 BHB attacks!"
```
- 前 8 条的调用栈里全是**厂商模块**（`oplus_*` 那一长串）⇒ 是**厂商模块重复注册 proc/sysfs** 的老毛病
- 我们的改动碰的是 **ipset dump** 与 **conntrack expect**，**都不注册 proc/sysfs 项** ⇒ 与它们无关
- 最后 1 条 eBPF 警告是**配置级提示**，我们没改 eBPF 配置

### 📌 记为基线（以后新增 WARNING 才是警报）
```
WARNING 总数 = 10（2026-10-03 17:0x，开机 72 秒时采）
  proc_register 重名 7 条 / sysfs 重名 1 条 / eBPF 提示 1 条
```
⚠️ **注意 opt37 那次记的是 0** —— 但那是**运行 4h37m 后**测的，
**环形缓冲已绕圈、开机日志已丢失** ⇒ 两次不可比。
**教训：`dmesg` 类计数必须在"刚开机"时采才有意义；晚采会得到假 0。**
