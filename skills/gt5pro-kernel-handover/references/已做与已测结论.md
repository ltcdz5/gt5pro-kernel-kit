### ★ 第 4 步（opt54）的结论 —— `get_hmbird_cpu_exclusive` 不由内核导出

- `get_hmbird_cpu_exclusive` 虽在 sched_ext 的缺符号清单里，但**由厂商模块 `oplus_bsp_game_opt.ko` 自己导出**
  （readelf 实证 `__ksymtab_gpl_get_hmbird_cpu_exclusive`，实现读它自己的 `es4g_cpumask_record`，与我们的 `iso_masks` 无关）。
  ⇒ **内核不得再导出同名符号** —— 那会**遮蔽**厂商定义（闸门1 硬禁止；opt6/test_task_ux 的致砖机制）。
  设备实测：先 `insmod oplus_bsp_game_opt.ko`（modules.load 第 225 行，早于 sched_ext 的第 239 行）⇒ sched_ext 的未知符号 **8 → 7**。
- 剩下 7 个（`iso_masks` / `ext_module_loaded` / `task_is_scx` / `scx_get_md_info` / `non_ext_task` / `hmbird_dir` / `__scx_ops_enabled`）
  全是 **GLOBAL（强）未定义引用，不是 weak** ⇒「内核不导出就拿 NULL 走跳过分支」不成立，不导出**根本装载不了**；
  且**全量 493 个 `.ko` 扫描证明只有 `oplus_bsp_sched_ext.ko` 引用这 7 个名字** ⇒ 导出它们不会翻动别的模块的守卫。
- 代价与边界：`scx_get_md_info()` 是**诚实的空实现**（`*vaddr = 0; *size = 0;`）、`task_is_scx()` 恒 false、
  `iso_masks` 只做保守初始化 ⇒ 这是「**可装载 + 不崩**」的最小可用面，**不是** OPPO hmbird 调度器的完整功能。

### ★ 闸门口径（最新，2026-10-08）

**三关，缺一不可**：
① `gate_new_exports.py` —— 导出集合：命中厂商 **新增=0 / 消失=0 / 遮蔽=0**；
② `gate_vko_crc.py` —— 厂商 493 个 `.ko` 的 `__versions` CRC 真值（**opt49-crc 起通过标准 = 0**）；
③ **`gate_all_modules.py`（全量 493 模块审计：缺失=0 且 CRC 不符=0）** —— 闸门2 对「**符号缺失**」是盲区
（opt53 的 `oplus_bsp_sched_ext` 缺 7 个符号就是它漏掉的），也拦不住 opt51 那种 493/493 全坏的配置改动。
审计的**符号全集 = 三者并集 = 内核导出 ∪ 厂商模块导出 ∪ 外部参考**（opt54 实测 = **21116**）。

## 改了什么（五类）

**A 网络向（当初的主要目的）**：默认拥塞 cubic→**BBR**（`TCP_CONG_ADVANCED=y`，另带 BRUTAL/VEGAS/WESTWOOD/HTCP/NV）；默认队列 pfifo_fast→**fq**；`IP_SET` 全家 15 项；`IP6_NF_NAT`/`IP6_NF_TARGET_MASQUERADE`；内嵌 `firmware/regulatory.db(+.p7s)` + `EXTRA_FIRMWARE`。

**B 上游修复**：stable 6.1.142~145、151~188 里**真参与本机编译的 97 个纯 `.c`** ＋ Oplus 09-14 同步批落地的 8 个（`VM_FAULT_RETRY_VMA` 缺页原地重试、`eventpoll` 的 `kfree_rcu` UAF、`unix/garbage.c` 的 `scc_index` fd 泄漏、`pipe.c` 环 `kvcalloc` 等）。⚠️ 性质是**正确性/CVE**，不是帧率也不是续航。
⛔ 已否证的做法："逐文件套 stable"——kernel.org 补丁的提交边界被压平 ⇒ 只能留纯 `.c`，并靠"make -k 普查 → 按报错 TU 退回"迭代；报错文件匹配必须 basename 兜底（`../kernel/cred.c` 这种）。

**C 构建与自检诚实性**：拆掉 builder 注入的 `config_fix` ⇒ **`/proc/config.gz` 不再谎报**（判据 `IP6_NF_NAT` 显示 `y`）；`gki_defconfig` 859→826 行、重复键 31→0；`setlocalversion` 后缀 `-ltcdz5-optN`；清掉树里残留的 `config.patch.*`、`cve-2026-43499-*.patch.*`。

**D 减脂（opt13）**：⚠️ **实际只有 `KFENCE_SAMPLE_INTERVAL=0` 一项生效**；
`UBSAN`（含 `TRAP`/`BOUNDS`/`LOCAL_BOUNDS`）与 `INIT_ON_ALLOC_DEFAULT_ON` **仍是原厂值 `y`（没关）**
—— 那三项当时只写在构建产物 `.config`、未进 git，后来的 config 归一化只把 KFENCE 记进 `gki_defconfig`。
**⇒ 另两项可补回**（纯减法，写进 defconfig 并提交）。

**E 故意没带 / 不跟**：无内置 KernelSU（root 走 init_boot 的 LKM）、**无 SUSFS**（`69_hide_stuff.patch` 从未应用，全树 susfs 命中 0）、不带第三方 root 模块、网络优化不带脚本；不跟第三方内核的 `scheduler=none`、`read_ahead`、关温控+GPU 拉满、`LTO_CLANG_THIN`（staticify ⇒ 撞符号消失砖闸）、关 KPTI/spectre/模块签名（安全降级属机主取舍，不替它做）。
